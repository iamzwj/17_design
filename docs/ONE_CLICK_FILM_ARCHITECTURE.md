# 一键成片：实施前架构方案

状态：首版实现与后续架构规划。2026-11-03。

首版实现说明：已采用 LangGraph JS 分阶段执行与独立 Worker。当前持久化采用项目独立文件和原子快照，恢复依赖保存的业务状态与供应商任务ID，不使用内存检查点冒充持久化；PostgreSQL、COS 和高并发租约仍是后续演进项。图片与视频同阶段各最多10个任务并行，前置素材完成后才调度依赖镜头；界面显示持久化的导演调度记录、六阶段进度与逐镜头生成状态。首版具备剧本分镜、角色场景设定、图片与镜头生成、辅助画面检查、生成音轨、对白字幕、MP4导出、局部重做与自然语言修改镜头。画面检查不确定时提示人工核对，不自动无限返工。字幕在支持libass的服务器烧录；其他FFmpeg环境嵌入字幕轨。素材只通过30分钟有效的签名链接提供给模型，签名密钥不进入项目响应。暂不提供私人角色照片上传。

## 产品入口与模型

视频生成展开为「视频创作」「一键成片」。原视频功能保留。一键成片使用独立项目列表和项目工作台，不混入单镜头视频任务。

- 文本：Gemini 3.1 Pro。
- 图片：默认 GPT Image 2.5，可选 Nano Banana 2.1。
- 视频：默认 MiniMax H3，可选 Wan 3.0。
- 模型在项目创建时保存；每次执行保存实际模型、参数和素材版本快照，修改项目默认值不改变已有任务。

## 参考项目与取舍

1. LangGraph：参考持久化状态、分支、人工介入与恢复机制。采用 JS 版本接入现有 Node 服务。图状态负责流程位置，业务表负责项目与生成任务，禁止出现两套互相矛盾的任务真相。
   https://docs.langchain.com/oss/javascript/langgraph/persistence
2. ComfyUI：参考提交前校验、执行队列、任务编号和历史记录的分离。用户界面采用分镜卡片，不直接暴露节点编辑器。
   https://docs.comfy.org/development/comfyui-server/comms_routes
3. Remotion：参考预览与渲染共用可序列化时间线。首版用受控时间线和 FFmpeg 导出；复杂编辑器及 Remotion 集成后置，需要时单独核对商业许可。
   https://www.remotion.dev/docs/timeline/render
4. HKUDS VideoAgent：作为视频理解、编辑工具分工的研究参考，不视为可以直接替代生产后台的现成平台。
   https://github.com/HKUDS/VideoAgent

## 工作台

项目概览 → 剧本 → 角色与场景 → 分镜与镜头 → 成片。

主区显示当前阶段可编辑成果，侧边显示导演对话、运行进度、预计与实际用量。自然语言修改先转换成可检查的结构化修改，再由相同执行入口应用；不让聊天模型直接改数据库或任意提交生成。

提供两种运行方式：
- 一键制作：输入故事与参数后自动执行，在预算范围内继续，失败时停在对应环节。
- 分步制作：计划和角色设定等关键阶段可确认后继续。

不要求每个镜头重复确认。多次失败、超过预算、修改影响多个镜头等情况才进入明确的待处理状态。

## 服务边界

现有 React 前端 → 现有登录与 Node API → 影片项目服务 → LangGraph JS 编排 → 独立执行 Worker → GRSAI / FFmpeg。

新增影片项目使用 PostgreSQL 保存业务状态和持久化检查点，现有账号及其他模块不迁移。先用数据库任务租约实现有限并发，规模增大后再引入专门队列，避免初期同时堆叠多个调度器。

Worker 的生成任务只提交一次并保存供应商 ID；后续轮询作为独立调度动作，不让长时间等待占满所有执行槽位。渲染单独限并发，不能堵塞 API 服务。

文件存储通过统一接口管理，原始图、参考图、视频、音频和成片分别保存；初期可复用服务器独立数据目录，COS 作为后续存储适配。供应商结果下载完成才算获得本地资产，不只保存会过期的远程 URL。

## 制作流程

输入 → 结构化剧本 → 角色/服装/场景设定 → 参考资产生成 → 分镜 → 首帧 → 分镜视频 → 规则检查与视觉检查 → 时间线 → FFmpeg → 成片。

Gemini 的编剧、资产设定、分镜、质检分别使用明确的输入输出结构。首版仅导演和修复判断允许有限工具决策，不把所有节点实现成自主 Agent。

角色、服装、场景日夜版本保存独立资产。分镜明确引用资产 ID 与版本。镜头提示词由统一结构生成，用户可修改；用户确认的版本作为此次执行快照。

先生成首帧，用首帧或角色参考绑定视频。首尾帧模式按供应商实际协议分别验证，不能因官网标注支持就直接承诺产品可用。

## 主要数据

Project：归属账号、名称、故事、时长、比例、风格、模型选择、预算、状态。
ScriptVersion：场次、事件、对白、预计时长、版本。
Asset / AssetVersion：角色、服装、场景、参考图；原文件、来源、版本、校验信息。
Shot / ShotVersion：顺序、时长、时间、角色与服装引用、场景引用、构图、动作、运镜、提示词。
GenerationAttempt：业务任务ID、输入快照摘要、供应商ID、状态、失败类型、实际用量、结果。
Review：确定性检查、视觉观察、置信度、问题证据、用户裁定。
TimelineVersion：镜头版本、素材入出点、播放次序、字幕、音轨、帧率、导出设置。
RenderJob：时间线版本、输出文件、进度和错误。

LangGraph 检查点只引用这些记录和版本，不把全部图片/视频二进制或无限聊天历史放入图状态。

## 恢复与费用控制

任务状态：queued / submitting / running / succeeded / failed / submission_unknown / cancelled。

提交供应商之前，先写提交记录。若请求超时且无法确认是否接单，标记 submission_unknown 并查询或人工恢复，不直接重发付费请求。业务幂等键包括项目、镜头版本、生成类型和参数摘要。

Worker 使用租约、心跳及重启恢复，回调与轮询结果去重。取消表示停止后续调度；上游不支持取消时仍查询收尾，明确可能产生的用量。

默认每镜头最多2次自动修复，并同时限制项目总费用、总尝试次数和修复耗时。网络错误、内容拒绝、能力不支持和画面不合格分别处理，不统一盲重试。

客户端切换模块、关闭页面和刷新不影响服务端任务。用户再次进入项目时直接读取保存的任务、输入与成果。

## 局部修改

依赖关系：剧本 → 资产/分镜 → 首帧 → 视频 → 时间线 → 成片。

更改服装先生成新版本，计算引用它的受影响镜头并标记待更新；旧成片继续可看，不直接删除或自动全量付费重生成。只改字幕不重生成视频，只改第六镜不重生成其他镜头。

执行结果必须绑定版本。旧任务晚返回时，保留历史结果但不得覆盖新镜头或新成片。

## 质检与声音边界

程序检查文件可解码性、真实时长、尺寸、黑帧、字幕溢出和时间线完整性。视觉模型辅助检查人物、服装、道具和场景，不把审美偏好自动判为失败。多帧检查、问题位置和修复建议都要保存，可人工放行。

实测已发现 MiniMax 的参考图视频可能把花盆变为手捧花，不能只检查人物相似度。

第一阶段支持保留/静音生成视频音轨、上传配音和音乐、编辑字幕。可控TTS、精确口型、声线克隆在供应商能力验证后再接入，不能用现有音轨冒充独立配音能力。

需要对白的项目先根据音频或预计语速规划镜头长度。所有片段统一帧率、分辨率、音频采样率、入出点；以实际帧数生成时间线，处理4秒请求返回4.46秒等差异。

## 落地顺序与验收

第一阶段：真实制作闭环。30秒、一个主要角色、一个场景、4–6镜头；项目/剧本/角色场景/首帧/视频/字幕/上传音轨/成片导出可用。支持9:16与16:9，一次项目只选一种比例；支持所定两种图片和两种视频模型，但按能力约束生成参数。

验收：实际导出可播放MP4、任务刷新和重启恢复、单镜失败不丢其他镜头、重复点击不重复付费、镜头重做只更新目标镜头、项目互不串数据。

第二阶段：2人、2场景、60秒；增加资产依赖更新、有限视觉修复、批量镜头调度、导演自然语言局部修改。

第三阶段：可控配音、音效、口型验证、丰富时间线编辑和更高质量自动剪辑。

当前缺口：Wan 尚未加入现有业务适配；生成接口实测成功不等于已完成产品接入。首尾帧、跨镜头角色一致性、多人同框和TTS尚无完整验收结果。
