# 蝶发设计工具：交付前回归清单

本清单汇总了当前项目 Git 修改记录和本项目历史任务中反复出现的用户反馈。任何涉及图像生成、任务卡、素材加载、浮层或部署的改动，提交前都必须逐项检查。

## 任务与请求

- 创建、再次生成和编辑后提交必须立即保留一张任务卡；请求超时、轮询失败或页面刷新不能让任务无提示消失。
- 失败任务保留提示词、参考图、模型、比例、真实分辨率和可用的“编辑”“再次生成”操作；失败时不渲染伪造或损坏的图片。
- 任务状态以服务端任务 ID 和可恢复的轮询为准，不能只依赖前端内存状态；同一任务不能重复提交到上游。
- 请求参数必须完整透传并持久化：模型、比例、分辨率、质量、数量、参考图及其顺序。
- 显示在任务卡上的比例和真实分辨率必须来自实际产物；请求的比例与实际比例不一致时应在服务端修正或明确失败，不能静默展示错误结果。

## 图片与参考图

- 优先请求、缓存并展示缩略图；缩略图完成后再加载预览原图，不能为了列表首屏逐张下载 4K 原图。
- 正在加载的结果图可以使用低干扰的缓慢羽化气泡；参考图未加载完成保持空白，不展示“加载中”文字。
- 图片加载失败只显示小号、非红色的失败提示；不得闪现浏览器的损坏图片图标、错误 URL 图片或替代文本。
- 已成功的图片应可直接拖入参考图区；参考图可排序、删除，顺序就是提交到模型的顺序。
- 任务信息前的参考图缩略图应在信息之前；打开的参考图浮层可用空白处或 Escape 关闭，关闭控件不能遮挡内容。

## 选择器、浮层与布局

- 创作器中的比例、模型、清晰度、质量等浮层不可使用会被浏览器裁切的原生下拉菜单；菜单需在可视空间中展开（底部创作器默认向上）。
- 所有浮层必须高于固定创作器、滚动列表和图片卡片；点击空白处与 Escape 均能关闭。
- 质量显示只使用 API 值：`low`、`medium`、`high`、`xhigh`、`max`，不增加“质量”前缀；只显示当前模型真正支持的档位。
- 桌面和窄屏下都要检查工具栏换行、触控点击区域、焦点样式和不被遮挡的菜单。
- 任何视觉或交互改动均须在浅色与深色主题检查对比度、悬停、焦点、禁用与错误状态。

## 性能、稳定性与部署

- 任务列表首屏应优先可交互，图片异步加载不能导致整页白屏、错位或长时间阻塞。
- 部署后必须验证 HTTPS 首页、静态资源、API 健康检查和 systemd/nginx 状态；若发布失败，先恢复可用服务再继续功能改动。
- 不能把部署目录、生成物、私钥、令牌或环境文件纳入 Git；部署配置和前端产物要使用同一版本。
- 每次修改都运行构建、静态检查和差异检查；涉及接口时补充最小参数/状态验证。

## 用户体验约束

- 除非明确需要，任务摘要不显示无意义的图片数量或绝对时间；显示信息应优先提示词、比例、真实分辨率、状态与操作。
- 空状态、加载状态和失败状态要稳定且克制，不能用大红字、冗长文案或突然消失来替代明确状态。
- 新增设计需保持现有圆角、轻玻璃层级和低干扰动画，并同时覆盖浅色、深色与移动端。
