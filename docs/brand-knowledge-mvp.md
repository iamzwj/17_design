# 团队品牌知识库（MVP）

入口：知识库 → 团队品牌知识库。文案（营销策划）、合规审核及通用图像创作顶部可选择品牌知识库；首版未接入节日海报、视频和其他专项工具。

## 初次配置

1. 管理员登录，在「团队权限」中将已注册成员加入三个组，可修改组名。
2. 选择品牌，为每组授予不可访问、查看、编辑、发布权限。成员属于多个组时取最高权限。默认未授权，管理员始终有管理权限。
3. 上传资料或新建文字，处理完成后核对分段，再由发布者发布。只有当前发布版本参与检索和生成。
4. 在 AI 工具输入框的品牌知识库参数中选择品牌。强制规则固定加载，普通资料按任务混合检索。生图可勾选最多三张已发布图片，和用户参考图共同受入口总张数限制。

## 范围与限制

- SQLite WAL 事务存储；本地 CPU 量化多语言 MiniLM 模型，384 维；中文分词关键词召回 + 精确向量余弦召回 + RRF 排序。首版不需要外部向量 API 或 GPU。
- 固定模型版本：Xenova/paraphrase-multilingual-MiniLM-L12-v2，revision `2c4055b12046f11709e9df2c122e59ffbdc2f900`。首次下载约 146MB，缓存后离线运行；模型准备失败会明确显示并支持重试。不会用关键词匹配冒充语义检索。
- 文件：PDF（最多100页）、DOCX、TXT、MD、PNG/JPG/WebP；单文件12MB；全库300份有效资料、10000历史分段、原件512MB。
- 上传后仍自动执行本地文字解析/向量化；打开资料详情可运行 Gemini 3.1 Pro 图文解析（扫描PDF也可），每次1至20页/张。PDF渲染原页；DOCX提取内嵌PNG/JPG/WebP，不支持WMF/EMF；暂无以图搜图、跨页全篇推理、PPT/Excel解析。原文件与解析页面保留，PDF中的矢量Logo导入为页面裁切PNG，不冒称矢量原文件。
- 图文解析经用户点击后，将所选页图和相关文字发送至已配置的GRSAI，按账户规则计费。结果保留主营、可读文字、规则、素材分类和来源；禁用/不确定素材不能直接导入。维护者核对文字和裁切位置后保存独立草稿，发布前不改变既有检索。图文预览另限512MB。
- Logo、色板、原始素材、风格参考分别归类。生图会接收已发布图片的等比衍生PNG。唯一正式Logo自动加载，多Logo须明确选择。默认在画面左上用正式Logo源图片等比叠加，可在知识库参数关闭；彩色Logo保留透明背景，不再默认添加白色底板；反白Logo在过亮背景上使用紧凑石墨底板。不重画或改色。保留叠加前成图及Logo版本、SHA256和位置。透明背景输出不执行该叠加。提示词要求模型不要自行绘制Logo，但无法保证模型绝不产生多余图形，最终仍需审稿。
- 编辑生成新版本；旧发布版本持续可用，发布新版本后原子切换。可发布历史就绪版本以回滚。停用/删除立即停止新检索，保留原件、分段和调用快照供追溯。
- 异步入库任务保存在数据库，切换模块、刷新和服务重启后恢复；失败任务保留便于重试。单线程后台队列，向量计算在独立Worker线程，避免占住HTTP主线程。
- 在线草稿在当前账号对应的浏览器存储；文件上传请求成功后原文件及任务在服务器保存。上传传输阶段离开页面可能需要重传，未收到服务器确认不要关闭浏览器。
- 同一资料有并发编辑检查。发布权包含编辑、停用和删除，首版没有多级审批。强制规则过长明确拒绝调用，不静默截断。
- 调用记录保存规则、命中片段和实际图片版本、图片SHA256、模型与任务ID。成员看自己的记录，管理员看全部；品牌授权撤销后不能继续读记录或原文件。
- 品牌私有内容仅在用户选择品牌并发起AI操作时，发送到现有文字/生图供应商；向量化在服务器本地执行。访客审核不提供私有知识库。
- 素材库与知识库共享 `shared/materialCatalog.js`。选择品牌时，已有的本品牌正式Logo直接自动加载，保留私有文件快照与SHA256，不需要重新上传或先关联。Logo默认彩色，可手动反白；卡通IP/真人IP可选，必须有对应已上传原图，不使用占位或另一类型替代。未标品牌的共享IP可经维护者关联到品牌。
- 生图品牌色固定加载已发布手册中含主色/标准色/辅助色/HEX/RGB/CMYK/Pantone等规范的分段，不依赖当次查询命中。界面检查颜色来源；未发布颜色规范时提示先发布，拒绝自行猜色。固定传递色值不等同于像素级验收，成图仍需审稿。
- 知识库“关联素材库”和素材卡片的“关联品牌知识库”可批量复用Logo/IP为可维护资料，按品牌编辑/发布权限处理；原文件字节不变，重复关联不重复建版本。源文件变化后重新关联会生成新版本，旧发布版本及旧调用快照保留。单独上传的IP在编辑页选择“卡通IP/真人IP”并发布后即可用于生图。

## 数据与运维

数据目录：`$DIEFA_DATA_DIR/knowledge/`，包含 `knowledge.sqlite`、WAL、`originals/`、`visuals/` 和 `models/`。原件、数据库不可放入公开静态目录。

发布工作流在重启前执行 `node server/knowledge/warmModel.js` 验证本地中文向量。可设置 `KNOWLEDGE_MODEL_CACHE` 指向预先下载的模型缓存。模型源仓库为 Apache-2.0，按源许可证使用。

备份需使用SQLite在线backup API，或停服后同时备份数据库、WAL、原件和visuals；模型缓存可重新下载。首版没有自动异地备份/高可用，不适合作为原文件的唯一备份。生产主机资源有限，达到配额后应扩容并迁移对象存储及独立数据库。

## 验证

`node --test tests/knowledge.test.js tests/textTasks.test.js`：权限、发布、版本切换、删除召回、原件访问、真实图片传递、历史快照、失败重试与数据库持久化。

`KNOWLEDGE_MODEL_CACHE=/path/to/cache node server/knowledge/warmModel.js`：真实本地中文语义模型。集成测试中的固定向量仅用于可重复的权限/状态测试，不代表语义质量验收。

## 2026-10-20 模型默认值

所有新生图入口默认 `gpt-image-2.5` / 1K / high，包括常规、对话、节日节气海报和标题；其他模型选项保留，历史任务/已选模型不回写。知识库图文解析固定 `gemini-3.1-pro`，本地向量模型保持不变。

## Logo重复修复

启用原图叠加时，正式Logo只用于后期合成，不传给生图模型；其他IP/风格原图照常传递，参考图序号与实际图片一致。生成提示要求预留品牌区、不自行画Logo。合成前用Gemini 3.1 Pro检查顶部已有标识，服务失败可回退Gemini 2.5 Pro。安全范围内的既有Logo仅在背景平坦时清除并放入一次正式原图，范围之外像素不改；复杂背景、边界不确定、疑似正文或服务失败不盲贴，保留底图并显示“Logo待核对”。底图、检测模型/位置、合成结果与错误状态均可追溯；任务停止会终止附加检查。此检查不是对整幅画面所有产品标识的全面品牌审核，完成图仍需审稿。


### 左上品牌区与单独重试

默认Logo宽度上限从画布24%减至18%，空白品牌区距上、距左统一按画布宽度5.5%留白；这是默认版式参数，不声称来自某一品牌手册。提示词要求标题遵循同一左侧版面基准并避让Logo。检测只查看左上36%宽、16%高的预留区，避免将右侧主标题送入标识检测；该区域像素极差每通道不超过10时可直接确认无可见标识，不调用语言模型。有内容时保留Gemini 3.1 Pro和2.5 Pro检查与保守拒绝覆盖机制。

瀑布流图片的“Logo尚未合成”提示提供“重试Logo”：使用原调用的Logo快照及`.before-logo.png`底图，不重新请求生图、不扣生图积分；必要的图文检查仍可能产生上游文本模型费用。重试状态服务端保存，切模块、刷新和进程重启可恢复；同一图片运行中的重复请求复用任务。成功生成新文件与缩略图，原先结果与底图保留。仅原任务所有者且仍有品牌访问权限可发起，不改原生图任务的成功状态。

Logo等距边距同时适用于空白区添加和已有标识替换：两者统一距上、距左为画布宽度5.5%，不再按旧检测框居中。合成前只裁去原素材完全透明的边缘，原始文件快照保持不变。旧标识仅在确认平坦背景后清除；若新的等距位置包含文字或复杂画面则拒绝覆盖，保留底图供核对。
